# 오목체스

체스기물로 상대의 연결을 끊고, 오목 두 줄을 먼저 완성하는 1대1 웹 보드게임입니다. 20×20 교차점에서 군사와 체스기물을 함께 사용합니다. 회원가입 없이 방 코드나 초대 링크로 입장합니다.

- **두 줄 승리:** 같은 색 군사·체스기물 다섯 개를 연결한 줄 두 개가 목표입니다.
- **전체 보호:** 완성된 줄의 다섯 기물 모두 이동·포획할 수 없습니다.
- **서버 판정:** 식량·이동·승패·시간은 서버가 확정합니다. 화면의 미리보기는 확정된 착수가 아닙니다.

## 설치와 실행

Node 버전은 [`.node-version`](.node-version), npm과 의존성은 [`package.json`](package.json)에 고정되어 있습니다. Node 26.13.1과 npm 12.2.3을 사용합니다.

```sh
# mise를 쓰는 경우. 이미 해당 Node/npm이 있다면 건너뜁니다.
mise install node@26.13.1
mise exec node@26.13.1 -- npm install -g npm@12.2.3
mise exec node@26.13.1 -- npm ci
mise exec node@26.13.1 -- npm run dev
# http://localhost:5173 — 두 개의 독립 브라우저 세션으로 접속
```

mise 없이 해당 Node/npm을 활성화했다면 `npm ci && npm run dev`로 실행합니다. 기본 개발 서버는 화면 5173, API 3000 포트를 사용합니다. 포트가 이미 사용 중이면 기존 프로세스를 확인하고 충돌을 해소하세요.

### 한 판 시작하기

```text
닉네임 입력 → 시작하기 → 방 만들기
초대 링크를 다른 브라우저/기기에 전달
두 플레이어가 준비 완료 → 흑 선공
군사 배치로 식량 획득 → 체스기물 배치/이동
연속 다섯 기물 두 줄을 완성 → 승리
```

같은 브라우저의 일반 탭은 동일한 세션입니다. 두 사람을 테스트하려면 일반 창과 시크릿 창, 서로 다른 브라우저, 또는 서로 다른 기기를 사용하세요. 같은 세션의 새 탭은 이전 연결을 교체합니다.

### PC 전술석 화면

너비 1200px·높이 640px 이상에서는 왼쪽 자원/배치, 가운데 보드, 오른쪽 시간/선택/확정의 3열 화면을 사용합니다. 기본 보기의 판 크기는 창의 너비와 높이에 함께 맞춰집니다. 확대하면 보드 내부를 스크롤하며, `전체 보기`로 되돌릴 수 있습니다.

장목 구간을 고르거나 서버 응답을 기다려도 확정 버튼은 오른쪽 하단에 유지됩니다. 조작 설명과 보호 줄 목록은 `조작·보호 줄`을 펼쳐 확인합니다. 좁거나 낮은 창에서는 같은 조작 요소가 세로 흐름으로 배치됩니다.

IBM Plex Sans KR 400/600을 서버에서 직접 제공하며 외부 폰트 서비스에 접속하지 않습니다. 피드백 전환은 120ms이며, 운영체제의 동작 줄이기 설정에서는 전환을 없앱니다.

## 게임 규칙

각 플레이어는 군사 20개, 룩·비숍·나이트·퀸 각 1개를 갖습니다. 시작 식량은 0개, 보유 한도는 5개입니다. 자기 턴에 아래 행동 하나를 수행합니다.

| 행동 | 비용·효과 |
|---|---|
| 군사 배치 | 빈 교차점에 공급처 군사 배치, 식량 +1; 최대 5 |
| 체스기물 배치 | 식량 3 소비, 공급처의 해당 기물을 빈 교차점에 배치 |
| 체스기물 이동 | 식량 2 소비, 체스 이동 규칙에 따라 이동·포획 |

군사는 이동·공격하지 않습니다. 식량이 5개여도 군사를 배치할 수 있지만 초과 식량은 받지 않습니다. 룩·비숍·퀸은 중간 기물을 넘지 못하고, 나이트만 뛰어넘습니다. 아군 포획과 제자리 이동은 금지입니다.

포획된 군사는 원래 소유자의 공급처로 돌아갑니다. 포획된 체스기물은 영구 제외됩니다. 포획에 따른 식량 보너스는 없습니다.

### 오목·왕관·장목

- 가로·세로·두 대각선에서 같은 색의 기물 다섯 개가 빈틈없이 이어지면 한 줄입니다. 종류는 섞을 수 있습니다.
- 한 줄당 왕관 2개를 표시하며 두 줄을 완성하면 승리합니다. 한 수로 두 줄을 완성해도 즉시 승리합니다.
- 6개 이상 연결하면 보호할 연속 5개를 선택합니다. 구간 선택도 턴 제한시간 안에 끝내야 합니다.
- 다른 방향의 줄은 기물을 공유할 수 있습니다. 기존 보호 기물을 이용해 새로운 교차 줄을 만들 수도 있습니다.
- 같은 직선에서 겹치는 5개 구간은 중복 득점할 수 없습니다. 같은 직선의 서로 겹치지 않는 두 구간은 인정합니다.
- 완성된 줄의 **다섯 기물 전체**는 이동 원점·포획 대상이 될 수 없습니다. 나이트가 보호된 기물 위를 뛰어넘는 것은 허용합니다.
- 장목에서 선택된 구간과 함께 인정할 수 있는 줄은 생략할 수 없습니다. 다만 서버가 사용자를 대신해 최대 점수 구간을 선택하지 않습니다. 10개 연속의 중앙 5개를 고르면 한 줄, 양 끝의 5개씩을 고르면 두 줄이 될 수 있습니다.

다음 턴 플레이어에게 합법적 행동이 하나도 없으면 해당 플레이어가 패배합니다. 임의 패스·별도 금수·체스의 체크·승격·캐슬링 규칙은 없습니다.

### 시간과 연결

- 한 턴은 60초입니다. 서버에 마감 시각까지 도착하지 못한 행동은 시간 초과 패배로 처리합니다.
- 서버가 연결 끊김을 확인하면 턴 시계를 멈춥니다. 플레이어별 경기 전체 누적 180초의 복귀 시간을 제공합니다.
- 재접속해도 이미 쓴 복귀 시간은 돌려받지 않습니다. 두 플레이어가 모두 연결되면 남은 턴 시간부터 재개합니다.
- 양쪽 모두 끊기면 각자의 복귀 예산이 줄어듭니다. 먼저 소진한 쪽이 패배하고, 정확히 동시에 소진하면 승자 없이 중단합니다.
- 새로고침 후 확정 보드·자원·자리는 복구하지만 아직 제출하지 않은 선택 초안은 사라질 수 있습니다.
- 서버 프로세스가 재시작되면 진행 중 경기는 승자 없이 **서버 중단**으로 종료합니다. 확정 보드와 결과는 보존합니다. 서버 재시작 후 자동 경기 재개는 제공하지 않습니다.

## 접속과 운영

### production build를 로컬에서 실행

해당 Node/npm을 활성화한 터미널에서 실행합니다.

```sh
npm run build
PUBLIC_ORIGIN=http://localhost:3000 npm start
# http://localhost:3000 — 화면과 API를 한 서버에서 제공
```

`NODE_ENV=production`은 HTTPS `PUBLIC_ORIGIN`과 명시적인 `DATABASE_PATH`를 요구합니다. 위 명령은 production build의 로컬 확인용이며 공개 서비스 보안 설정이 아닙니다.

설정 예시는 [`.env.example`](.env.example)에 있습니다. 필요하면 `.env`로 복사하고 환경에 맞게 수정합니다. 기존 `.env`를 덮어쓰지 마세요. 환경변수는 실행 시 로드되며 비밀값·DB 파일은 커밋하지 않습니다.

| 설정 | 의미 |
|---|---|
| `HOST` | 기본 `127.0.0.1`; LAN 노출은 `0.0.0.0` |
| `PORT` | API/운영 화면 포트, 기본 `3000` |
| `PUBLIC_ORIGIN` | 브라우저가 사용하는 정확한 scheme·host·port; 허용 Origin |
| `DATABASE_PATH` | SQLite 파일 경로, 기본 `data/omokchess.sqlite` |
| `NODE_ENV` | `production`이면 보안 쿠키·운영 설정 검사 |

### 같은 Wi-Fi의 휴대전화로 실행

빌드 후 `HOST=0.0.0.0`, `PUBLIC_ORIGIN=http://<PC의-LAN-IP>:3000`으로 서버를 실행하고, PC와 휴대전화 모두 그 주소로 접속합니다. 방화벽에서 해당 포트가 허용되어야 합니다. 로컬 테스트용 HTTP는 신뢰하는 네트워크에서만 사용하세요. 세션 쿠키 보호를 위해 인터넷 공개 운영은 HTTPS가 필요합니다.

공개 운영 시 TLS reverse proxy가 WebSocket upgrade를 전달해야 합니다. 서버는 단일 프로세스와 쓰기 가능한 영속 SQLite 경로를 사용합니다. 동일 DB를 여러 경기 서버가 동시에 소유하거나 네트워크 파일시스템으로 공유하는 구성은 지원하지 않습니다. DB/WAL/SHM 파일은 실행 중 임의 복사·삭제하지 말고 SQLite에 맞는 백업 절차를 사용하세요.

대기 방은 30분 후 만료합니다. 종료 경기와 명령 영수증은 종료 후 7일 보존합니다. 세션 토큰은 HttpOnly 쿠키에만 두며, 방 코드나 닉네임으로 기존 자리를 되찾을 수 없습니다. 쿠키를 지우거나 다른 기기로 옮기면 같은 사람이어도 기존 플레이어로 인증되지 않습니다.

## 개발과 검증

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium firefox webkit
npm run test:e2e
```

`npm run check`는 typecheck·단위/통합 테스트·빌드를 순서대로 실행합니다. E2E는 별도 명령이며 빌드된 서버를 실행합니다. 각 브라우저 worker는 독립 서버·임시 SQLite·임시 포트를 사용하므로 다른 실행의 세션·요청 제한과 섞이지 않습니다. worker 종료 시 서버와 임시 DB를 정리합니다. Playwright trace와 screenshot은 실패 분석용이며 `test-results/`에 저장됩니다.

- [`src/game`](src/game): 순수 이동·자원·포획·오목 엔진.
- [`src/protocol/messages.ts`](src/protocol/messages.ts): 외부 입력·공개 상태 스키마.
- [`src/server`](src/server): 권위 판정, 세션, SQLite, HTTP/WebSocket.
- [`src/web`](src/web): 한국어 화면, 보드, 입력, 미리보기, 재접속.
- [`tests`](tests): 규칙과 실제 DB/서버 경계 검증.
- [`e2e`](e2e): 실제 두 브라우저 세션의 입장·착수·승패·모바일·재접속 검증.
- [실행 계획](plans/technical-plan-omokchess-online.md): 규칙 근거, 태스크 경계, 인수 기준.

브라우저 테스트 대상은 Chromium·Firefox·WebKit 및 모바일 emulation입니다. emulation 결과를 실제 iPhone/Android 실기기 검증으로 해석하지 마세요. 동시 방 수·인터넷 지연에 대한 부하 측정치는 아직 없습니다.

기여 변경은 관련 테스트와 문서를 함께 갱신하고, 다른 작업자의 변경을 섞어 커밋하지 않습니다. 원격 게시·배포는 로컬 구현과 별개의 승인 작업입니다.
